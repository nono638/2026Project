Data

Data · CSV downloads & column dictionary

Everything the gallery charts is built from raw per-row CSVs. They’re published here so anyone can verify the numbers in the dashboards, reproduce the analyses, or run their own. Sidecar JSONL files carry the per-row LLM-call traces and the BSOD-resilience heartbeat events. Sizes are modest enough for direct download; the larger files (Experiments 1 and 2) are 20–30 MB.

Downloadable datasets

Sidecar files

Two JSONL files travel alongside each experiment’s CSV. They’re not in the dashboards but they’re essential for forensic deep-dives.

Sidecar Format What’s in it File
events.jsonl (Exp 1) One JSON object per line, ~150 KB Heartbeat events from the runner: run_start, config_start, row_done (with running call total + last in-flight call), gpu_snapshot, row_rest_start/tick, config_end, run_end. Built to shrink the BSOD blast radius from one snapshot-interval to one row. experiment_1_events.jsonl
traces.jsonl (Exp 1, going forward) One JSON object per row, variable size Per-row LLM-call trace: list of every OllamaLLM.generate call the strategy made, with intent label, prompt, response, latency. Empty for rows produced before the per-row instrumentation shipped (see Writeup » Exp 1/2 oversights). generated on next run

Column dictionary

All columns that appear in the experiment CSVs, grouped by purpose. Not every column is present in every file — older runs predate some additions.

Identifiers

ColumnTypeMeaning
strategystring RAG strategy name: naive, self_rag, multi_query, corrective, adaptive (Exp 1 only).
chunkerstring Chunking strategy: fixed, recursive, sentence, semantic (Exp 2 only).
modelstring Ollama model tag used for generation.
questionstring HotpotQA question text. Joins back to the original dataset via exact match.
dataset_namestring Source dataset (always hotpotqa currently).
dataset_sample_seedint Random seed used to sample the question subset (always 42).

Gold-standard metrics

ColumnTypeMeaning
gold_answerstring Reference answer from HotpotQA.
rag_answerstring The model’s generated answer.
gold_f1float [0,1] Token-level F1 between rag_answer and gold_answer.
gold_exact_matchbool True if gold_answer appears verbatim in rag_answer (case-insensitive substring).
gold_bertscorefloat [0,1] BERTScore F1 between rag_answer and gold_answer (microsoft/deberta-xlarge-mnli).

Per-judge scorer metrics

Each judge in the panel contributes five columns, prefixed with a safe-name slug of the judge identifier. <judge> below stands for the slug (e.g. anthropic_claude_haiku_4_5_20251001, openai_gpt_5_4_mini). The number of judges varies by experiment — Exp 1/2 use a 2-judge panel, Exp 0 v3 ran up to 12 judges for the validation comparison.

ColumnTypeMeaning
<judge>_faithfulness float [1,5] Judge’s 1–5 rating: how well the rag_answer is supported by the retrieved context.
<judge>_relevance float [1,5] How well the rag_answer addresses the question.
<judge>_conciseness float [1,5] Whether the rag_answer avoids unnecessary verbosity.
<judge>_quality float [1,5] Mean of the three sub-metrics — the judge’s composite quality score.
<judge>_scorer_latency_ms float Wall-clock latency of this judge’s scoring call.
consensus_quality float [1,5] Mean of per-judge quality across the active panel — the primary metric the dashboards use.

Latency

ColumnTypeMeaning
strategy_latency_msfloat Time from strategy.run() call to return — covers retrieval + every LLM call the strategy made.
scorer_latency_ms_totalfloat Sum of per-judge scoring latencies.
total_latency_msfloat Sum of the two above. Useful for end-to-end cost.

Failure diagnostics

ColumnTypeMeaning
context_sent_to_llmstring The exact context (retrieved chunks concatenated, post-filter) the answer-generation call saw. Can be tens of KB — the bulk of the row size.
failure_stagestring Substring-attribution: which pipeline stage is most likely responsible for a wrong answer. One of none, chunker, retrieval, filtering, generation, unknown.
failure_stage_confidence string Confidence label for the stage attribution (high, medium, low, n/a).
failure_stage_method string Detection method used — currently substring.
gold_in_chunksbool True if the gold answer appears in any chunk the chunker produced.
gold_in_retrievedbool True if the gold answer appears in any chunk that came back from retrieval.
gold_in_contextbool True if the gold answer appears in the post-filter context sent to the model.

Pipeline metadata (held constant within an experiment)

ColumnTypeMeaning
chunk_typestring Chunker family: recursive, fixed, sentence, semantic.
chunk_sizeint Target chunk size in tokens (where applicable).
chunk_overlapint Overlap between adjacent chunks in tokens.
num_chunksint Total chunks the chunker produced for the source document.
embed_providerstring Embedder provider, e.g. ollama.
embed_modelstring Embedder model tag.

retrieval_modestring Retrieval mode: hybrid, dense, or sparse.
retrieval_top_kint How many chunks the retriever returned.

context_char_lengthint Character length of context_sent_to_llm.
reranker_modelstring|null Reranker model name (null when no reranker was used — the default for Exp 1 and 2).
reranker_top_kint|null Top-k after reranking.
llm_providerstring LLM provider (always ollama).
llm_hoststring Ollama host URL or local.
llm_modelstring Ollama tag used for generation.
llm_quantizationstring Quantization level reported by Ollama /api/show at runtime (e.g. Q4_K_M, Q8_0), or unknown.

LLM-call provenance (Phase 1 instrumentation, going forward)

Added with the per-row trace work documented in the Writeup’s Exp 1/2 oversights section. Rows produced before that instrumentation shipped have prompts_source set to reconstructed_minimal_2026-05-20; new rows are tagged recorded.

ColumnTypeMeaning
n_llm_callsint Number of LLM chat completions the strategy made for this row. For NaiveRAG always 1; variable for branchy strategies.
llm_call_intentsstring Pipe-separated intent labels in call order, e.g. rate_relevance|rate_relevance|generate_answer. See Writeup for the label vocabulary per strategy.
final_promptstring The literal substituted prompt sent to the answer-generation call (the last call in the trace). Reconstructed for NaiveRAG backfill rows; recorded verbatim for new rows.
prompts_sourcestring recorded for rows produced by the instrumented runner; reconstructed_minimal_2026-05-20 for historical backfilled rows.
code_shastring 7-char git HEAD SHA at generation time, so an analyst can pin which version of src/strategies/ produced the row. Empty on backfilled rows.
llm_num_predictint Token-generation cap passed to Ollama (OllamaLLM.DEFAULT_NUM_PREDICT, currently 1024).
llm_keep_alivestring Model-residency hint passed to Ollama (30m).
n_total_calls_inc_embed int Backfill-only: total Ollama calls (chat + embed) attributable to this row, derived from events.jsonl deltas. Not a substitute for the precise n_llm_calls — it lumps embedder calls in.
n_token_* · not yet present — Per-call prompt / completion token counts. See the audit table on Writeup row 4 — on the Phase 2 backlog.

Example usage

A few snippets for common analyses. They assume pip install pandas and that you’ve downloaded one of the CSVs above.

Load Experiment 1 and reproduce the per-strategy ranking

import csv, pandas as pd

# raw_scores.csv has rows with multi-KB context fields; raise the limit
# or pandas will choke on the largest cells.
csv.field_size_limit(2**31 - 1)

df = pd.read_csv("experiment_1_raw_scores.csv", engine="python")

ranking = (
    df.groupby("strategy")["consensus_quality"]
      .agg(["mean", "std", "count"])
      .round(3)
      .sort_values("mean", ascending=False)
)
print(ranking)
# strategy      mean    std  count
# naive        4.340  0.840   1199
# multi_query  4.334  0.818   1200
# corrective   4.268  0.881   1200
# adaptive     3.594  1.252   1200
# self_rag     2.992  1.073   1196

Filter to rows produced by the new instrumentation

# Recorded rows have the full per-call trace; reconstructed rows are
# schema-aligned but don't carry intermediate LLM outputs.
recorded = df[df["prompts_source"] == "recorded"]
backfilled = df[df["prompts_source"].str.startswith("reconstructed", na=False)]
print(f"recorded: {len(recorded)}  backfilled: {len(backfilled)}")

Join the per-row LLM-call trace back to the CSV

import json

traces = {}
with open("experiment_1_traces.jsonl") as fh:
    for line in fh:
        rec = json.loads(line)
        traces[(rec["strategy"], rec["model"], rec["question"])] = rec["trace"]

def get_trace(row):
    return traces.get((row["strategy"], row["model"], row["question"]), [])

df["trace"] = df.apply(get_trace, axis=1)
df["n_chat_calls_recorded"] = df["trace"].str.len()
# For recorded rows this should equal n_llm_calls; for backfilled rows
# trace will be [] and n_chat_calls_recorded will be 0.

Compare model size on a fixed strategy

fixed_strategy = df[df["strategy"] == "naive"]
by_model = (
    fixed_strategy.groupby("model")[["consensus_quality", "gold_f1"]]
      .mean()
      .round(3)
      .sort_values("consensus_quality", ascending=False)
)
print(by_model)
